## PRODUCTION

### PROD-1 — Long single-output Write calls silently fail at the output-length boundary and LOSE all in-flight work; chunk >~15–20KB to disk, then concatenate  — NEW · MED (authoring-runtime; not in ledger)
- **Source (verbatim, `C--AEGIS/feedback_chunked_write_discipline.md`, Bo 2026-04-30):** *"A single Write call producing ~140KB of markdown content terminated abruptly without writing the file. The pattern is: large single outputs hit a token / output-length boundary and the entire generation is discarded. There is no recovery mechanism after the boundary is hit."* Cure: *"Write each chunk to a separate `_part_NN_<topic>.md` file … After all chunks are committed to disk, use `cat _part_*.md > final_filename.md`."* Threshold: *"any output likely to exceed ~15-20KB should be chunked."* When NOT to chunk: Edit-tool diffs, file moves, JSON/YAML configs, normal-length code.
- **Why book-relevant:** BOOKSMITH writes large artifacts directly — `seed.md` (§1–§7 Book Bible can be large), the assembled master markdown, long digests, and — critically — full chapter prose. A chapter or a seed written in one Write call that crosses the output-length boundary will silently vanish with zero recovery, which is *catastrophic mid-book*. This is the WRITE-side analogue of the READ-side 8K/2000px guards the ledger already has (§1.1, §10.3). The §15.1 survival primitive ("write every completed unit to disk the instant it is done") assumes the write SUCCEEDS; this rule protects the write itself.
- **Ledger status:** MISSING. The ledger has read-side size discipline (chunk >8K to READ; resize >2000px to VIEW) and the disk-atomic survival primitive (§15.1), but no WRITE-side output-limit rule. Genuine gap.
- **Bake-in:** §15.1 (survival) or a new §3/§10 note: for any large original-prose write (a long chapter, `seed.md`, the assembled master, a big digest) likely to exceed ~15–20KB, write it in `_part_NN_*.md` chunks to disk then concatenate — a single oversized Write can hit the output-length boundary and discard the entire generation with no recovery; keep the part files as provenance. Excludes Edit diffs, moves, and config writes. Priority: **MED** (raise if any book unit routinely exceeds ~15KB per write).
