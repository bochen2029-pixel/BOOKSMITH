Ordered by structural leverage. Each delta: lesson (verbatim where it matters) · source · what the kit template/ledger has · ABSENT/WEAKER/WRONG + HIGH/MED/LOW · bake-in. Short CONFIRMATIONS at the end (so a future pass does not "fix" them).

## D1 — NO per-book `ARCHITECTURE.md` template exists; both instances have one and the taxonomy names it a root doc  ★ TOP DELTA · ABSENT · HIGH

- **Lesson (both instances carry a full `ARCHITECTURE.md`).** BOOK-test3 header, verbatim: *"Contract-first source of truth. Bo's Solo Enterprise Architect methodology applied to the third book. If `SEED.md` and this file ever conflict, this file is the invariant; `SEED.md` is the instantiation."* AI_BOOK's is 232 lines with **The Three Load-Bearing Disciplines**, **The Generative Chain** (a full ASCII pipeline `CLAUDE.md→SEED.md→contracts/→registry/→…→export→outputs/`), a numbered **Invariants (never violated)** list (11–15 items), **Dependencies**, **Phase gates**, **Ship Criteria** (with an explicit *"A book does NOT ship if…"* negative list), and a **Meta-Architectural Rule**.
- **What the kit has.** Ledger §2.1 lists `ARCHITECTURE.md` as one of the "5 root docs" of the scaffold, and quotes its precedence rule verbatim. `KIT_ARCHITECTURE.md` §b names `ARCHITECTURE.md` in the kit-level tree — **but there is NO `templates/architecture.template.md`.** `templates/` ships seed/contract/handoff/threads/state/WRONG/digest only (verified: `ls templates/`). The kit collapsed the per-book ARCHITECTURE into the kit-level `KIT_ARCHITECTURE.md` (the invariant machine). That is correct for the *machine* invariants, but it means a kit-built book gets **no book-specific invariant/ship-criteria doc** — the thing both instances treat as their contract-first source of truth.
- **Delta:** ABSENT (HIGH). A from-scratch book has no place to record *its own* load-bearing disciplines (canon-wall vs canon-exposed; corrections-carried; cadence), *its own* invariants list, *its own* ship criteria + "does NOT ship if" gate, or *its own* generative-chain diagram. `KIT_ARCHITECTURE.md` is book-agnostic by design; it cannot hold "the Ten Corrections must each land" or "N=2 is the v1.0 integration gate." The precedence rule the ledger quotes ("SEED is the instantiation; ARCHITECTURE is the invariant") is *unenforceable per-book* if the per-book ARCHITECTURE doesn't exist.
- **Bake-in:** Ship `templates/architecture.template.md` with the instances' proven skeleton: (1) **The Single Load-Bearing Specification** (the "reads as one authorial act" clause, book-specialized); (2) **The Generative Chain** ASCII block; (3) **Invariants (never violated)** numbered list, pre-seeded with the kit universals (append-only versioning; append-only WRONG; authorship-class authoritative; forbidden-vocab absolute; canon citations verifiable; 1M baseline; full-prior-prose-before-drafting) + `{{BOOK_SPECIFIC_INVARIANTS}}`; (4) **Phase gates**; (5) **Ship Criteria** with a matching **"does NOT ship if"** list; (6) **Dependencies**; (7) a footer changelog line. Add `ARCHITECTURE.md` generation to `generate seed` (GATE-2) so every book gets one. Cross-reference from ledger §2.1 and `KIT_ARCHITECTURE.md` §b. Update `seed.template.md`'s footer (it already says "Companion to CLAUDE.md… book_config.json"; add `ARCHITECTURE.md`).

- **Lesson (verbatim).** AI_BOOK §3 contract fields: *"Must Callback… **Must Flash-Forward (explicit forward pointers per §4.2 of CLAUDE.md)**… Delivers…"*. BOOK-test3 ARCHITECTURE Generative Chain: *"contracts/*.md → Per-part specification (Intent, State I/O, Seeds, Callbacks, **Flash-forwards**, Class, Canon anchors, Corrections-carried)."* AI_BOOK ARCHITECTURE Phase-A gate lists *"Must Plant / Must Callback / **Must Flash-Forward** / Constraints fields populated."*

## D5 — Command grammar's audit set is FIXED; both instances declare BOOK-SPECIFIC audits (`canon-wall`, `corrections`, `compensation`)  · ABSENT · HIGH

- **Lesson (verbatim).** AI_BOOK: **`audit canon-wall`** *"command runs automatically pre-commit. Flags any hit"* (SEED §1.7), plus **`audit compensation`** *"verifies these numbers appear consistently across chapters. Drift is a failure"* (SEED §5.2) and **`audit dependencies`**. BOOK-test3 ARCHITECTURE invariant 6: **`audit corrections`** *"must pass — each of SEED §6's corrections has found its surgical insertion point"*, plus **`audit vocabulary`** and **`audit canon`**. AI_BOOK ARCHITECTURE Ship Criteria requires all four (`canon-wall`, `dependencies`, `compensation`, plus Steelman/Skeptic) green.
- **What the kit has.** CLAUDE.md §3 / `KIT_ARCHITECTURE.md` §d fix the audit vocabulary to **`audit threads | dependencies | canon | voice | refrain`**. There is no mechanism for a book to **register a custom audit** (a per-book consistency gate keyed to that book's load-bearing invariant). `lint_manuscript.py` reads `book_config.voice` blacklist (which *approximates* `audit canon-wall` for named-framework atoms), but there is no general "declare a book-specific audit + wire it into the ship gate" seam.
- **Delta:** ABSENT (HIGH). These are not decorative — AI_BOOK's ship gate literally *requires* `audit canon-wall` green (zero framework names) and `audit compensation` green (numbers consistent Ch1↔Ch13); BOOK-test3's *requires* `audit corrections` green (all Ten Corrections landed). A kit book that can't declare its own invariant audit has no gate for its central discipline. The canon-wall case is partly reachable via the blacklist, but `audit compensation` (cross-unit number consistency) and `audit corrections` (each item-in-a-checklist landed in an assigned unit) have **no kit analog at all** — and both are recurring shapes (any book with recurring specific numbers, or any reforge/correction book, needs them).
- **Bake-in:** Add a `book_config.audits[]` array — each entry `{ name, kind, spec }` where `kind ∈ {forbidden_terms | cross_unit_consistency | checklist_landed | custom}`. Generalize the audit runner so `audit <name>` dispatches to the declared kind: `forbidden_terms` → `lint_manuscript.py` atom set (canon-wall); `cross_unit_consistency` → grep each `spec` number/entity across all units and diff (compensation); `checklist_landed` → verify each item in `spec` appears in its assigned unit (corrections). Wire declared audits into GATE-4 / `export`'s ship gate so a book's own invariant is enforced. Ledger: add §2.x "Book-specific audits (declared in config; wired into the ship gate)."

## D6 — Two-tier export (`v0.9` preview + `v1.0`) with epistemic-disclosure discipline is a real shipped pattern the kit's single `export v1.0` doesn't model  · ABSENT · MED

- **Lesson (verbatim, AI_BOOK ARCHITECTURE Discipline 3 + Ship Criteria).** *"ship v0.9 preview edition with explicit epistemic disclosure and integrate N=2 as empirical validation in v1.0."* Two full ship-criteria blocks: **v0.9 Preview Edition** ("Ch 9 frames four-of-five sectors as analytical projections… preview-edition disclosure present in Intro closing paragraph + back-cover") and **v1.0 Release Edition** ("N=2 shipped + integrated… preview-edition disclosure removed… v0.9 readers receive v1.0 update"). Ledger: extend §2.9 (ship gate) with the preview-edition option.
